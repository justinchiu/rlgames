The update rules

Every rule has the same inputs at each decision: the current policy pi and q[a], the expected payoff of each action against the opponent's current policy. They differ in what they optimize, what state they keep, and how they turn it into the next policy.

The game and its goal

A[a][b]     payoff to player 0 when 0 plays a, 1 plays b
            (player 1 gets −A[a][b])
q_0 = A y,  q_1 = −Aᵀ x     each action's payoff vs the other's policy
v = Σ_a π(a) q(a)           value of the current policy

goal (Nash):   max_x min_y  xᵀ A y
exploitability e(x, y) = ½ [ max_a (A y)_a − min_b (xᵀ A)_b ]
                       = 0 exactly at a Nash equilibrium

Shared inputs, in code

v   = pi @ q        # value of the current policy
adv = q - v         # advantage == instantaneous regret

Where the objectives come from

Policy gradient ascends each player's own payoff with the opponent frozen. Regret matching optimizes no fixed function, because each q_t depends on the opponent's next move. Its update is chosen so the next advantage vector is orthogonal to R⁺ (Σ_a R⁺(a)(q(a) − v) = 0, derived). Then Φ = Σ_a (R⁺(a))² grows at most linearly, so regret ≤ √Φ = O(√T) (Hart and Mas-Colell, cited). When both players have average regret ε, the average policies form a 2ε-Nash equilibrium (cited). The magnet rules solve a KL-regularized game; one step is the mirror-descent update
π' = argmax_π η π·q − KL(π ‖ π_t) − ητ KL(π ‖ m),
whose closed form is the logit update shown (derived).

The average every rule can report (orange)

avg_num += w_t * pi     # w_t = t for CFR+, 1 otherwise
avg_den += w_t
avg = avg_num / avg_den

Policy gradient

State: logits θ. One step from where you are.

def pg_update(theta, pi, q, t, lr):
    adv = q - pi @ q
    theta = theta + lr * pi * adv
    return theta, softmax(theta)

Regret matching

State: regret totals R. No step size.

def rm_update(R, pi, q, t):
    R = R + (q - pi @ q)
    return R, regret_matching(R)

Regret matching+ (CFR+)

Clipped totals; players take turns.

def rmplus_update(R, pi, q, t):
    R = np.maximum(R + (q - pi @ q), 0)
    return R, regret_matching(R)
# player 1's q uses player 0's NEW pi

Magnet, fixed uniform

State: logits θ, pulled toward magnet m.

def magnet_update(theta, pi, q, t, lr, tau, m):
    theta = (theta + lr * q
             + lr * tau * np.log(m)) / (1 + lr * tau)
    return theta, softmax(theta)

m = uniform        # never changes

Magnet, APMD resets

Magnet jumps to the current policy every K steps.

m = pi0                       # start: the initial policy
for t in range(T):
    if t > 0 and t % K == 0:
        m = pi.copy()         # reference reset
    theta, pi = magnet_update(theta, pi, q, t, lr, tau, m)

Magnet, EMA

Magnet drifts toward the current policy at rate ρ.

m = pi0
for t in range(T):
    theta, pi = magnet_update(theta, pi, q, t, lr, tau, m)
    m = (1 - rho) * m + rho * pi

Where each one stops

Setting the magnet update's new logits equal to the old ones gives pi[a] ∝ m[a] · exp(q[a] / τ). At the true equilibrium every q is equal, so a fixed point there requires pi = m. A fixed magnet only lands on the ★ if it sits on the ★. A moving magnet (APMD, EMA) can, because at its own fixed point m = pi.

In a game tree like Kuhn poker

Each information set gets its own q. Policy gradient weights each history by reach_self · reach_opp and estimates it by sampling games. CFR uses cfv(I, a) = Σ reach_opp(h) · q(h, a), computed exactly, without reach_self. The average policy then weights each iteration by reach_self.
